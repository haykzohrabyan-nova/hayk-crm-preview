What Is BazaarPrinting CRM?
A full internal CRM built for a B2B printing company

Purpose

BazaarPrinting CRM manages the full customer journey — from the first contact (lead) through quote generation, customer approval, production, and payment. Every step is tracked, every action is logged, and the right people see the right information at the right time.

📥 Lead Management

SDRs capture and validate incoming leads. They screen, hold, or route leads to the Sales team. All activity is tracked in a full timeline.

📝 Quotes & Orders

Sales or SDRs create quotes with line items, pricing, discounts, and delivery details. Quotes are sent to customers via Email, SMS, or WhatsApp.

✅ Customer Approval

Each quote has a private link. The customer clicks, reviews the quote, and confirms — converting it into an order automatically with an ORD-YYYY-NNN reference code.

💳 Payment Tracking

Orders track payment status (Unpaid / Partial / Paid) and deposit status. Payment reminder links can be sent via Email, SMS, or WhatsApp directly from the order page.

👥 CRM & Customers

Every customer is saved to the CRM. Quotes auto-create customer profiles. Duplicate customer detection runs in real time when entering phone numbers.

📊 Role-Based Access

SDRs, Sales reps, and Admins each see a different view. Actions are gated by role. Admins have full override capability on any record.

🔒 Lead Locking (Soft-Lock)

When an SDR claims a lead, locked_by_id is set. Other SDRs see a "Being worked by [Name]" banner and view it in read-only mode. The lock is NOT released on drawer close — only when the SDR Routes, Rejects, or an admin force-releases it. This keeps the lead attributed to the right SDR even across sessions.

Won Tracking
How the system tracks successful conversions for SDRs and Sales
🏆
A lead is marked "Won" automatically — not manually — when the linked ticket is released to production (ticket_status = in_production). Order conversion alone does not count as Won; payment gates and production release must pass first.
🔍 SDR Won Tab

SDRs have a "Won" tab in their workspace showing all their leads whose linked ticket entered production. Each row shows:

  • Order reference (ORD-YYYY-NNN)
  • Total value ($)
  • Closer's name (who closed the deal)
  • Customer info
💼 Sales Won

Sales reps see "Won" in their dashboard KPIs. Won count and Won Value use tickets in in_production or completed. The lead's sales_status is auto-updated to "Won" when production release succeeds via:

  • Payment confirmed + auto-release (cash, accountant confirm, net terms)
  • Manual production release by staff
  • Customer confirm that immediately passes production gates

  • Follow-up schedule
  • Special requirements & internal notes
💰 Two Order Flows
Quote First

Send a quote for the customer to review and approve online. They get a private link, review everything, and click "Confirm & Accept." This auto-generates the order.

Direct Order

Customer is already committed. Skip the quote step — send a payment link directly. Good for walk-in customers or repeat clients.

Record Locking
Protecting confirmed orders from accidental changes
🔒
Once a customer confirms a quote, the record is locked for all SDR and Sales users. They can view it and send payment reminders, but they cannot edit the line items, pricing, or cancel the order. Only an Admin can make changes or cancel a confirmed order.
📋 Lock States
SituationSDR / SalesAdmin
Draft or Sent quote ✅ Can edit & cancel ✅ Full access
Customer-confirmed order 🔒 View only + send payment reminders ✅ Full access (edit & cancel)
Manually converted order (rep) 🔒 View only + send payment reminders ✅ Full access
Cancelled ticket 🔒 View only 🔒 View only
✅
Payment reminders are always available regardless of lock state. A locked order can still have its payment link sent via Email, SMS, or WhatsApp directly from the order page — this is a separate action from editing.
🔗 Lead Lock vs SDR Attribution (Soft-Lock Model)

Two separate fields track lead ownership — they serve different purposes and must not be confused:

FieldSet whenReleased whenPurpose
locked_by_id Any user opens a lead (POST /lock) SDR routes or rejects (POST /unlock). Closing the drawer alone does NOT release it. Admin can force-release. Prevents simultaneous editing — shows "Being worked by [Name]" banner. Drives Owner column and SDR "My Leads" toggle.
sdr_id SDR only — set via POST /lock when roleName === "sdr" Only by admin via POST /reassign (unassign action) Permanent SDR attribution — drives scoped tabs (Hold, Directed to Sales, Won, Rejected). Never overwritten by sales users opening a lead.

✏️ Admin Lead Editing

From the Leads → All Leads table, admins see an Edit button on every row. Clicking it opens the lead detail drawer in editable mode — no lock required. The footer shows Close and Save Changes instead of SDR workflow buttons.

ℹ️
Admin edits bypass the lock guard on the API — the lead doesn't need to be unclaimed for admin to edit it.
👤 Admin SDR Assignment

Every lead row in the All Leads table shows an Assign or Reassign button for admins. The label and modal options are driven by the lead's locked_by_id field:

ConditionButtonModal
locked_by_id IS NULLAssignSDR dropdown only — no Unassign option; Confirm disabled until SDR picked
locked_by_id IS SETReassignSDR dropdown + "— Unassign" option at top

Calls POST /api/leads/[id]/reassign which updates locked_by_id, sdr_id, and locked_at. "Unassign" sets both to null.

🛡️ Terminal State Override

A terminal lead is one that has been Rejected, Won, or Dropped. Normally these are fully read-only for everyone. Admins are the exception — they see an amber "Admin Override" banner and can edit any field, re-route the lead, or change its status.

Terminal StateSDR / SalesAdmin
Rejected 🔒 Red banner — view only, no actions 🟡 Amber "Admin Override" banner — fully editable, can re-route
Won 🔒 Red banner — view only 🟡 Amber banner with caution: "Editing will NOT cancel the linked order — handle that manually in Tickets"
Dropped 🔒 Red banner — view only 🟡 Amber banner — fully editable
✅
The API already enforces this — it allows admin edits on terminal leads. Only the UI was updated to match. Non-admins still hit a 403 if they somehow call the endpoint.

User Sessions & Security
Idle sign-out, session logging, and admin visibility

Why It Exists

The CRM contains sensitive customer and pricing data. If a user walks away from their computer, the system will automatically sign them out after a configurable idle period — protecting the account and logging the event for the admin.

⏱️ How Idle Detection Works
User is active
Any mouse move, click, key press, or scroll resets the idle clock.
2 minutes before timeout
A blocking warning modal appears with a live countdown and a "Stay Signed In" button.
Timeout reached
Session is ended, event logged as "auto" sign-out, user redirected to /login.
⚙️ Configuration

Set in Admin → Company Settings → Session & Security:

SettingValue
Idle timeout5 – 480 minutes (default: 20)
Warning shownAlways, 2 min before sign-out
Applies toAll roles — SDR, Sales, Admin
📄
A plain-English /policy page explains session tracking to users. No login required. Linked from the idle warning modal.

Per-user KPI cards Total sessions · Active time · Auto sign-out count · Green "active now" dot

Dashboard KPI cards "Active Users" (signed in right now) and "Idle Sign-outs (7d)" on the Admin dashboard.
Sign-out reasons logged manual — user clicked Sign Out · auto — idle timeout · unknown — browser crash / session expired
